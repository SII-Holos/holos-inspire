## Image Registry Model

Two independent registry systems (images NOT shared between them):

**Main registry (all spaces except SJ):**
- Push domain: `docker-qb.sii.edu.cn`
- Display domain: `docker.sii.shaipower.online` (assigned by platform after registration)
- Submit tasks using display domain, NOT push domain

**SJ registry (SJ资源空间 only):**
- Push domain: `docker-t.sii.edu.cn`
- Display domain: `docker-t.sii.shaipower.online`

**Push workflow:**
1. Use `inspire_image_push(image="local-image:tag", name="镜像名称", tag="版本号")` to push to Harbor
   - `name` must NOT include project prefix (use 'faro-postgres', NOT 'inspire-studio/faro-postgres')
   - Tool auto-prepends `inspire-studio/` and handles docker login/tag/push
2. **MUST register** on platform: 镜像管理 → 新建镜像 → fill 镜像名称 + 版本号 → save
3. Use display domain address in task submission: `docker.sii.shaipower.online/inspire-studio/<镜像名称>:<版本号>`

Without registration, the image exists in Harbor but CANNOT be used for tasks, notebooks, or inference services.

**Manual push (if tool unavailable):**
1. `docker login docker-qb.sii.edu.cn` (credentials from 镜像管理 → 本地推送)
2. `docker tag <local> docker-qb.sii.edu.cn/inspire-studio/<镜像名称>:<版本号>`
3. `docker push docker-qb.sii.edu.cn/inspire-studio/<镜像名称>:<版本号>`
4. Register on platform (same as step 2 above)

Without registration, the image exists in Harbor but CANNOT be used for tasks, notebooks, or inference services.

**Harbor credentials:**
- 七宝 and 松江 have different passwords (same username pattern: robot$inspire-studio+user-xxx)
- Credentials shown on first visit to 镜像管理 → 本地推送 page. Save them carefully.
- Requires VPN or campus network to push

**Image saves (from notebooks):**
- Only saves container filesystem changes (`/usr/local`, `/root`, etc.)
- Does NOT save mounted storage (`/inspire/hdd/...`)
- Clean caches before saving: `apt clean && pip cache purge && rm -rf ~/.cache`
- Images >100GB may fail to save

## Resource Specs (spec_id / quota_id)

Each task type has its own set of resource specs, obtained via the resource_prices API:

| Task Type | schedule_config_type | Example Specs |
|-----------|---------------------|---------------|
| GPU Training | SCHEDULE_CONFIG_TYPE_TRAIN | 1/2/4/8 GPU with matching CPU/memory |
| HPC/Slurm | SCHEDULE_CONFIG_TYPE_HPC | CPU-only configs (16/32/55 cores) |
| Notebook (DSW) | SCHEDULE_CONFIG_TYPE_DSW | 1/2/4/8 GPU or CPU-only |

- spec_id = quota_id (same value, different name in different contexts)
- Training and notebook spec_ids are NOT interchangeable
- Specs can expire when platform updates configurations
- Use `inspire_status` to see current available specs per compute group
- Omit `spec` in submit tools to see a table of available specs

## Storage Architecture

```
/inspire/hdd/project/{project_en_name}/        ← HDD, shared across ALL spaces in same project
/inspire/ssd/{workspace_id}/{project_en_name}/  ← SSD, higher performance
/inspire/hdd/global_user/{username}/            ← Personal global directory (cross-project)
/inspire/hdd/project/{project_en_name}/public   ← Team-shared directory within project
```

- Same project = same storage, regardless of which space
- Different projects CANNOT see each other's storage
- Deletion is **IRREVERSIBLE** (GPFS has no recycle bin or snapshots)
- Check quota: `df -h /inspire/hdd/project/{name}/`
- Expand project quota: contact advisor or apply via Feishu approval
- Expand personal quota: Feishu → 审批 → 算力平台存储申请

## Priority & Scheduling

- Each project has a max priority (shown in `inspire_status`)
- Priority 1-3: **preemptable** — can be killed when resources are tight
- Priority ≥4: **safe** — will NOT be preempted
- Same priority: smaller tasks (fewer GPUs) are scheduled first
- Multi-node tasks: all requested nodes must be simultaneously available
- Low-utilization GPU instances may be auto-reclaimed (policy varies by space)

## Budget (点券)

| Project Type | Refresh Period | Refresh Time | Notes |
|-------------|---------------|-------------|-------|
| 导师/标杆/火炬/科学智能 | Quarterly | Start of Jan/Apr/Jul/Oct | Previous balance cleared |
| 公共科研项目 | Weekly | Monday ~10:00 | 672 points per user |

- Budget ≤0 may block task creation
- Workaround: low-priority CPU tasks (priority 1-3) are exempt from budget
- Max GPU quota per 导师项目: 32 cards (adjustable by request)

## VPN & Network

- VPN (aTrust): single device only, no concurrent logins
- Campus network: no VPN needed, direct access
- DNS for internal domains: set to `10.11.26.11`
- HuggingFace mirror: `export HF_ENDPOINT=https://hf-mirror.com` (online spaces only)
