# SII 启智平台 — Inspire Tools Guide

Use this skill when the user wants to run experiments, manage Docker images, or check GPU resources on the SII 启智 AI platform.

## First-Time Setup

If inspire_config shows no defaults configured:

1. Run `inspire_status` to discover projects, workspaces, compute groups, and available resource specs
2. Set defaults (per Synergy user, applies to all sessions):
   ```
   inspire_config(action="set", key="defaultProject", value="项目名")
   inspire_config(action="set", key="defaultWorkspace", value="分布式训练空间")
   inspire_config(action="set", key="defaultImage", value="docker.sii.shaipower.online/inspire-studio/xxx:tag")
   inspire_config(action="set", key="defaultPriority", value="9")
   inspire_config(action="set", key="defaultShm", value="1200")
   ```
3. After setup, `inspire_submit` only needs `name`, `command`, `compute_group`, and `spec`

Note: `spec` (spec_id) and `compute_group` are NOT stored as defaults — they vary by workspace and task type. Use `inspire_status` to see available specs, then pass them directly.

### ⚠️ Do NOT set `commandPrefix`

`commandPrefix` is a **Synergy-wide global** applied to EVERY `inspire_submit` command regardless of project. Setting it breaks whenever:
- You have multiple research projects in parallel (each with different conda envs / code paths)
- You switch project context mid-session
- A different agent / sub-session uses inspire_submit with an unrelated command

**Correct pattern**: write env init in every `command` explicitly:
```
command="source /opt/conda/etc/profile.d/conda.sh && conda activate myenv && cd /inspire/hdd/project/{en_name}/code && python train.py"
```
It's 2 extra lines per submit, but zero cross-project interference.

If a previous session left `commandPrefix` set, clear it:
```
inspire_config(action="set", key="commandPrefix", value="")
```

## Core Workflows

### Submit a GPU training job

```
inspire_status()                                              → discover workspaces, compute groups, specs
inspire_submit(name="exp-001", command="python train.py",
  compute_group="cuda12.8版本H100", spec="<quota_id>")        → submit (spec from status output)
inspire_jobs(status="running")                                → monitor
inspire_job_detail(job_id="job-xxx")                          → check details if failed
inspire_logs(job_id="job-xxx", lines=50)                      → view logs
inspire_metrics(job_id="job-xxx", time_range="30m")           → check GPU utilization
```

If you omit `spec`, the tool shows a table of available specs — pick one based on the task's resource needs.

### Submit an HPC (Slurm) job

For CPU-intensive tasks. HPC space has no internet — all deps must be in the image.

```
inspire_submit_hpc(name="preprocess", entrypoint="python preprocess.py",
  workspace="高性能计算", compute_group="高性能计算", spec="<quota_id>",
  image="docker.sii.shaipower.online/inspire-studio/slurm-xxx:tag",
  number_of_tasks=2, cpus_per_task=4, memory_per_cpu="8G")
```

### Deploy an inference service

```
inspire_models(action="list")                                  → find model_id
inspire_inference(action="create", name="llama3-serving",
  model_id="xxx", model_version=1, spec="<quota_id>",
  command="python -m vllm.entrypoints.openai.api_server",
  image="docker.sii.shaipower.online/inspire-studio/vllm:tag",
  port=2400, replicas=1)
inspire_inference(action="detail", serving_id="sv-xxx")
inspire_inference(action="stop", serving_id="sv-xxx")
```

### Create a notebook (interactive development)

```
inspire_notebook(action="create", name="dev-env",
  compute_group="4090-cuda12.8", spec="<dsw_quota_id>",
  image="docker.sii.shaipower.online/inspire-studio/xxx:tag")
```

Note: notebook specs differ from training specs. Omit `spec` to see available notebook specs.

### Prepare and push a Docker image

```
inspire_images(search="torch")                                → find existing registered images
inspire_images(source="harbor", search="torch")               → search raw Harbor registry
inspire_image_push(image="my-train:v1")                       → push to Harbor (name defaults to image name)
```

After push, you MUST register the image on the platform: 镜像管理 → 新建镜像 → fill 镜像名称 (same as name param, e.g. 'my-train') + 版本号 (same as tag, e.g. 'v1') → save. Without registration, the image cannot be used for tasks or notebooks.

Note: `name` parameter should NOT include project prefix (use 'faro-postgres', NOT 'inspire-studio/faro-postgres'). The tool auto-prepends `inspire-studio/`.

### Download data for offline training

Offline spaces (分布式训练空间, 高性能计算) have NO internet. To prepare data:

1. Submit a download job in an online space (same project → shared storage):
   ```
   inspire_submit(name="download-model", workspace="CPU资源空间",
     command="export HF_ENDPOINT=https://hf-mirror.com && huggingface-cli download meta-llama/Llama-3-8B --local-dir /inspire/hdd/project/{en_name}/models/llama3-8b",
     compute_group="CPU资源-2", spec="<cpu_spec_id>", priority=2)
   ```
2. Wait for download to complete
3. Submit training in offline space — the data is accessible at the same path

### Capture and read training output

Always redirect output to a file:
```
inspire_submit(name="exp-001",
  command="python train.py 2>&1 | tee /inspire/hdd/project/{en_name}/logs/exp-001.log")
```

To read results: `inspire_logs(job_id="job-xxx")` or submit a lightweight CPU job to cat the log file.

## Command Templates

Copy-paste templates with correct env init, log capture, and storage paths. Replace `{en_name}` with the project's English name (from `inspire_status` output).

### 4090 (可上网GPU资源, online)

```
inspire_submit(
  name="exp_007",
  workspace="可上网GPU资源",
  compute_group="4090-cuda12.8-2",
  spec="<train_spec_id>",
  image="docker.sii.shaipower.online/inspire-studio/myproject:v1",
  command="source /opt/conda/etc/profile.d/conda.sh && conda activate myenv && "
          "cd /inspire/hdd/project/{en_name}/code && "
          "python train.py --seed 42 "
          "2>&1 | tee /inspire/hdd/project/{en_name}/logs/exp_007.log",
  priority=9)
```

### H200 / H100 (分布式训练空间, OFFLINE — all deps must be in image)

```
inspire_submit(
  name="exp_008",
  workspace="分布式训练空间",
  compute_group="cuda12.8版本H100",     # or H200-* / cuda12.9版本H100
  spec="<train_spec_id>",
  image="docker.sii.shaipower.online/inspire-studio/myproject:v1",
  command="source /opt/conda/etc/profile.d/conda.sh && conda activate myenv && "
          "cd /inspire/hdd/project/{en_name}/code && "
          "python train.py --config large.yaml --seed 42 "
          "2>&1 | tee /inspire/hdd/project/{en_name}/logs/exp_008.log",
  shm=65536,                            # ≥64GB for multi-GPU
  priority=9)
```

### CPU (CPU资源空间, online, free tier at priority 1-3)

```
inspire_submit(
  name="eval-exp_007",
  workspace="CPU资源空间",
  compute_group="CPU资源-2",
  spec="<cpu_spec_id>",
  command="source /opt/conda/etc/profile.d/conda.sh && conda activate myenv && "
          "cd /inspire/hdd/project/{en_name}/code && "
          "python eval.py --checkpoint /inspire/hdd/project/{en_name}/ckpts/exp_007/last.pt "
          "2>&1 | tee /inspire/hdd/project/{en_name}/logs/eval-exp_007.log",
  priority=3)    # priority 1-3 is budget-exempt
```

### HPC/Slurm (高性能计算, OFFLINE, multi-node CPU)

```
inspire_submit_hpc(
  name="preprocess",
  workspace="高性能计算",
  compute_group="高性能计算",
  spec="<hpc_spec_id>",
  image="docker.sii.shaipower.online/inspire-studio/slurm-xxx:tag",   # MUST have "slurm" in name
  entrypoint="source /opt/conda/etc/profile.d/conda.sh && conda activate myenv && "
             "bash /inspire/hdd/project/{en_name}/code/scripts/preprocess.sh",
  number_of_tasks=2,
  cpus_per_task=4,
  memory_per_cpu="8G")
```

### Data download job (run in online space, data visible to offline space via shared storage)

```
inspire_submit(
  name="download-llama3",
  workspace="CPU资源空间",
  compute_group="CPU资源-2",
  spec="<cpu_spec_id>",
  command="export HF_ENDPOINT=https://hf-mirror.com && "
          "huggingface-cli download meta-llama/Llama-3-8B "
          "--local-dir /inspire/hdd/project/{en_name}/models/llama3-8b",
  priority=3)
```

## Key Platform Rules

### Images & Registries
- **Two registries**: main (docker-qb.sii.edu.cn → docker.sii.shaipower.online) for all spaces except SJ; SJ-only (docker-t.sii.edu.cn → docker-t.sii.shaipower.online)
- **Push ≠ usable**: after docker push, must register on platform via 镜像管理 → 新建镜像 (fill 镜像名称 + 版本号)
- **Submit uses display domain**: always use docker.sii.shaipower.online/... (not docker-qb.sii.edu.cn/...)
- **Harbor auto-creates repos**: no need to pre-create the repository, push will create it automatically
- **Harbor credentials**: 七宝 and 松江 have different passwords

### Resource Specs
- **spec_id varies by task type**: training, HPC, and notebook each have different spec lists
- **Query dynamically**: use `inspire_status` or omit `spec` in submit tools to see available specs
- **Avoid fragmentation**: for large training, pick whole-node specs (e.g., 8 GPU) rather than single-GPU specs

### Compute & Scheduling
- **Priority ≥4**: won't be preempted. Priority 1-3: can be killed by higher-priority tasks.
- **Low-priority CPU tasks (1-3)**: exempt from budget — useful when budget is exhausted
- **Non-interactive shell**: ~/.bashrc NOT loaded. Must `source /opt/conda/etc/profile.d/conda.sh && conda activate myenv` explicitly in every command. Do NOT use `commandPrefix` — see "First-Time Setup" for why.
- **Offline spaces**: no pip install, git clone, wget. All dependencies must be in the Docker image.
- **Distributed training env vars**: platform auto-injects MASTER_ADDR, MASTER_PORT, PET_NNODES, PET_NODE_RANK, PET_NPROC_PER_NODE

### Storage
- `/inspire/hdd/project/{en_name}/` — shared across ALL spaces in same project
- `/inspire/hdd/global_user/{username}/` — personal global directory
- Deletion is **irreversible** (GPFS has no recycle bin)
- Check quota: `df -h /inspire/hdd/project/{name}/`

### Budget
- 导师项目: refreshed quarterly. Max 32 GPU cards.
- 公共科研项目: 672 points/user/week (Monday ~10:00)

## Task ID Prefixes
- `job-xxx` → GPU training task
- `hpc-job-xxx` → HPC/Slurm task
- `sv-xxx` → Inference serving

Tools auto-detect the type by prefix.
